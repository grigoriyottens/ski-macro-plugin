# Изменения в ERP

Прочитай перед любой записью. Общего запрета на изменения нет; действуют явный запрос пользователя, реальные методы, бизнес-правила и права подключения.

## До вызова

1. Установи компанию, сущность и точный объект. Для обновления прочитай актуальные значения через API; для создания проверь необходимые поля и существующие совпадения разрешённым ограниченным поиском.
2. Раздели намерения: «проанализируй/подготовь правки» не равно «сохрани в ERP». Не меняй сумму, согласование, файл или адресатов по догадке. Если значение, версия файла или цель неоднозначны — задай конкретный вопрос.
3. Проверь, что нужный инструмент предоставлен текущему подключению и его схема поддерживает требуемое действие. Наличие записи в `help.tools` не заменяет доступный инструмент. Если его нет, объясни ограничение; не пиши REST-обход, не используй сайт и не расширяй права ключа.
4. Ясного запроса на точное обычное обратимое изменение достаточно: не требуй ритуального второго подтверждения. Для удаления, необратимых действий, платежей, существенных финансовых/юридических последствий, массовых изменений или отправки третьим лицам проверь, что именно этот объём и последствия явно согласованы; при отсутствии такого согласования кратко покажи действие/цели и запроси подтверждение. Соблюдай обязательные подтверждения клиента. Уже полученное точное подтверждение не запрашивай снова без изменения условий.

## Выполнение и проверка

- Выполни только запрошенное изменение, без дополнительных объектов, адресатов или «заодно исправлений».
- Проверь фактический результат через подходящий метод чтения API/статуса. Различай «принято», «выполняется», «завершено», «отклонено», «результат неизвестен». Не заменяй проверку снимком MacroData.
- При ошибке прекрати операцию и сообщи её смысл. Если запись могла произойти до тайм-аута/обрыва ответа, не повторяй её автоматически: скажи, что исход неизвестен и повтор может создать дубль. Продолжать проверку/восстановление после такого сбоя — по запросу пользователя. При последующем разрешённом повторе используй предусмотренную схемой идемпотентность, если она существует, а не выдуманный параметр.
- Для массовой операции заранее зафиксируй выборку и объём; остановись при ошибке. Отчитайся отдельно об успешно изменённых, не выполненных и неопределённых объектах. Не объявляй всю операцию успешной при частичном результате.
- В ответе назови объект и изменение простым языком. Не выводи секреты или большой сырой ответ. «В MACRO ничего не изменено» допустимо только когда это известно, а не после неопределённого исхода записи.

## Добавить вложение не значит заменить

По текущему каталогу `documents.uploadFile` добавляет новое вложение, в том числе при совпадении имени. Запрос «замени» нельзя молча превратить в добавление или в пару «удалить + добавить». Если метода замены нет, объясни это и спроси, устраивает ли добавление новой версии; не трогай старый файл без соответствующего запроса.

При явно запрошенном добавлении и наличии инструмента:

1. Установи документ и конкретный файл; прочитай актуальную схему `uploadFile`.
2. Передавай ровно один источник: уже имеющуюся разрешённую прямую HTTPS-ссылку `sourceUrl` **или** `fileBase64`. Для локального/созданного файла сначала измерь размер инструментом.
3. Текущий сервер допускает прямой файл до 1 МиБ (1 048 576 байт); лимит клиента может быть ниже. Base64 формируй программно, не вручную и не выводи в ответ. Если клиент не умеет прочитать/закодировать файл, не изображай передачу.
4. Не загружай корпоративный файл в публичное хранилище ради URL. Если имеющийся способ не подходит, сообщи ограничение; новый сервис или публикация требуют отдельного явного решения пользователя.
5. HTTP 202 означает только приём заявки. Сохрани возвращённый `uploadId`; проверь `documents.getFileUploadStatus(uploadId)`. В пределах текущего хода сделай не более трёх проверок статуса с указанным сервером интервалом, без длительного блокирующего ожидания. Если всё ещё выполняется, сообщи это; не отправляй файл повторно и не запускай фоновый мониторинг без просьбы.
6. `rejected`/`parked` означает завершение без добавления вложения. При успехе проверь возвращённые метаданные и при необходимости список файлов документа. Если проверка статуса сама завершилась ошибкой, сообщи неизвестный итог и остановись.

Сведения о `uploadFile` проверены по предоставленному инструменту 18.09.2026, но реальная тестовая запись при сборке навыка не выполнялась. Общая статья MACRO MCP содержит противоречащую каталогу фразу о недоступности загрузки: при такой коллизии проверяй текущую схему, а не запрещай весь сценарий по старой статье.
